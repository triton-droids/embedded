# Integration update — 2026-10-19

Branch: `Humanoid_ros2`. Dates in this update use America/Los_Angeles.
This records software changes, verification and outstanding work; it is not a
claim of successful robot operation or a hardware commissioning report.

## 1. Original model action, PD and limits

- Restore the ONNX export's original zero default posture, 0.2 action scaling,
  raw previous-action observation and absence of a fixed [-1, 1] action clamp.
- Load Kp/Kd from model metadata and target angle bounds from the companion
  training XML. Kp is 100 for the hip/thigh joints, 80 for knees and 20 for ankles;
  Kd is 1. No integral gain is introduced.
- Validate the configured registry against model hash, joint order, gains and
  saved angle limits; reject legacy runtime-policy overrides.
- Update configuration synchronization and regression tests while preserving
  motor IDs/models, direction, encoder offsets and linkage calibration.
- Retain the 50 Hz tracking contract and `hardware_verified: false` guard.

## 2. Independent CAN communication and per-joint expiry

- Add a repository-owned nonblocking transport adapter without editing the
  installed SDK. Reuse MIT encoding while separating one TX owner and per-bus RX.
- Dispatch actual status/fault frames by interface, motor and host identity;
  preserve receive age, reject unrelated frames, and latch local transport faults.
- Replace the command FIFO with a bounded lifecycle/latest-target mailbox.
  Whole target batches coalesce, wake TX immediately, and do not accumulate.
- Remove synchronous RX/ACK waits and per-motor enable sleeps from TX. Complete
  enable asynchronously from a fresh healthy status report for that joint.
- Preserve per-joint monotonic command deadlines, inhibit expired motors and
  require a fresh explicit enable for recovery; repeat transmissions cannot
  extend command lifetime. Retry failed disable submissions.
- Add `/can_timing` counters, reduce high-frequency command logging, and join
  communication workers before closing their buses on shutdown.

## 3. Joint freshness and asynchronous inference

- Track complete finite q/dq and source/receipt freshness for every required
  joint. Other-joint traffic cannot renew a missing joint. Launches provide the
  complete selected registry order to the C++ controller.
- Move ONNX inference to one independent worker while ROS feedback/estop/status
  callbacks continue. Use the latest immutable snapshot; no inference FIFO or
  catch-up bursts. Keep previous-action history tied to accepted outputs.
- Gate reported IMU/joint timestamp skew at 20 ms by default and use IMU source
  timestamps for gravity integration; reject duplicate/reordered IMU samples.
- Recheck the original input snapshot after inference and reject expired,
  over-budget, nonfinite or post-estop/shutdown results. Default inference-work
  budget is 20 ms; it is a configured threshold, not measured Jetson capacity.
- Add `MotorCommand.valid_until`. Preserve oldest source time and earliest expiry
  through C++ hold/forwarding and CAN retransmission, with local monotonic expiry.
- Clear cached commands/hold state on existing disable transitions to prevent
  stale enable/target replay. Existing source-time validation remains in effect
  for legacy publishers with zero `valid_until`.

## 4. Advisory safety integration

- Independently monitor `/safety/status` in the C++ controller. Missing, stale or
  unhealthy supervisor diagnostics produce warnings only. Defaults: 3 s startup
  grace, 0.5 s heartbeat freshness threshold, 1 Hz evaluation and 5 s log throttle.
- Validate source and monotonic receipt age; unrelated/replayed diagnostic
  samples do not renew supervisor liveness.
- Change optional `SafetyFeature` failures/exceptions to `Output.warnings` while
  continuing current command selection. Expose warnings in Python bindings and
  throttle their ROS logs. Production registers no concrete SafetyFeature.
- Preserve existing explicit estop, state freshness, command timeout and CAN
  timeout disable behavior. No IMU-module takeover or new physical threshold is
  introduced by this advisory-warning change.

## 5. Body IMU micro-ROS source

- Add a separate ESP32-S3 raw-body-IMU sketch, distinct from the head controller.
  It has no servo/motor output; requested telemetry is 200 Hz over binary serial
  micro-ROS at 460800 baud, with SI units and no orientation estimate.
- Synchronize to Agent epoch time and stamp register-read start before I2C/DDS
  transport. Suppress publication when sync fails or ages out; reconnect entities
  and resynchronize. Bounded maintenance may skip sample periods.
- Default the tracking launch to an external IMU publisher. Keep the legacy JSON
  reader explicitly opt-in so it does not compete with an Agent for the port.
- Firmware compilation/flashing and the external attitude/QoS contract remain
  unverified integration work. Host-comparable read stamps do not prove physical
  synchronization with motor feedback.

## 6. Read-only ROS network Web/RViz modes

- Add `web`, `rviz`, combined `monitor`, and explicit `all` modes to the safety
  launch; preserve `supervisor` as its existing default.
- Add a ROS telemetry cache/HTTP Web node with bounded per-joint data, source and
  receipt freshness, optional registry identity/temperature metadata and unknown
  values for unavailable telemetry. Reject HTTP control POST requests.
- Reuse the existing motor Web table styling while omitting SDK/CAN ownership,
  control, enable, calibration and tuning buttons. Default HTTP binds locally.
- Move the joint-state visualization relay into the safety package, retaining
  the old motor-package executable as a compatibility wrapper.
- Connect selectable feedback to the visualization topic and optional local
  robot_state_publisher/RViz, with the manual joint GUI disabled. Nodes inherit
  ROS network/domain settings; browser display uses HTTP, not DDS directly.

## 7. Architecture and documentation

- Add English node topology and control-data-flow diagrams as PNG/SVG plus
  editable Graphviz sources. Distinguish isolated ONNX bench and hardware paths.
- Enclose deprecated application SDK paths in a dashed red boundary; explicitly
  note that the legacy gateway/demo defaults have not been disabled.
- Replace the root README's old architecture image and add source/scalable-image,
  safety-mode and full architecture links.
- Document command lifetime, asynchronous IO/inference, warning behavior,
  external IMU integration and software-only verification recipes.

  command publisher. Graphical RViz and cross-host LAN were not tested.
- Isolated C++ relay smoke test passed: source/expiry preserved and expired

  timing or real-model ONNX execution was verified in this update.

and rebuild/restart C++/Python consumers of the changed control-core output API.
Do not mix old/new message definitions or clear the hardware guard to make a
launch start. Keep physical calibration separate from software test success.
